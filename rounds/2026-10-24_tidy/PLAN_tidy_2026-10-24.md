# PLAN — tidy the working directory (2026-10-24)

Owner, 2026-10-24: "why do we have batches of images over several directories … have a sub-agent order our
working directory, and then write an index of where what is … 'brilliant programmer creates good program and
then dies, and then nobody knows how he organised his things'."

Planner and executor: Fable (sub-agent), cloud clone for code and tracked moves, the owner's Mac (VM) for the
untracked pictures. Record of what was run: `APPLIED_tidy_2026-10-24.md`. Move table: `moves_2026-10-24.csv`.

## 1. What was wrong

- The picture of a card could be in any of six folders — `out_phrases_v3/round2`, `out_phrases_v3`,
  `out_deck_f62`, `out_deck_a2`, `out_phrases_a2`, `out_deck_sent` — plus `images/` (the 1.x WebP masters);
  `build_apkg.py` searched them in a kind-specific order and took the first hit (`A1_IMAGE_DIRS`,
  `A2_IMAGE_DIRS`, `SENT_IMAGE_DIRS`). 2,004 key-named pictures for 1,452 cards; the losers sat beside the
  winners with nothing marking them. Each folder also held its ledger, plan, QA sheets, driver, `_rerolled/`.
- Audio in two folders by level (`audio/` for the 520 base words, `audio_a2/` for the rest), each with `_superseded/`.
- The root held two old packages (v2.1), two superseded documents whose live versions are in `docs/`, the old
  changelog, a retired script and a closed data file, next to ~20 live scripts and 6 live data files.

## 2. The design (spec §13)

```
media/images/<key>.<ext>                 the ONE current picture of every card (1,452)
media/images/_history/<old batch path>/  every other picture, at its old path: shadowed renders, _rerolled/,
                                         _superseded/, images/<key>.webp (the 1.x masters)   (1,055)
media/audio/<key>.mp3, <key>_s.mp3        the ONE current take of every key (668; audio/ + audio_a2/ merged)
media/audio/_history/                    replaced takes (6)
media/generation/<batch>/                ledger.csv, plan.json, cards.csv, gen_log.jsonl, QA sheets, README,
                                         gen.py and helpers — the text record of each render batch, no pictures
```
Why this and not something else:
- **One folder, one file per key** is the rule a stranger can verify by eye and `check_layout.py` can enforce.
  The build loses its six-way search (`IMAGE_DIR`, `AUDIO_DIR`); the recorder, ingest tool, QA gate and golden
  set read the same two folders.
- **History keeps the old path** (`_history/out_deck_f62/0027_suo.png`), so every ledger, QA sheet, round report
  and build manifest written since July still reads; nothing is renamed, only re-homed. The move table is the
  old→new map, with a sha1 per file.
- **The batch folders keep their names under `media/generation/`** for the same reason; their `gen.py` drivers
  stay with their ledgers and now write new pictures straight into `media/images/` (re-rolls to
  `_history/<batch>/_rerolled/`), so generation and build agree on where a picture is.
- **Code and live data stay at the root.** Moving ~20 modules and 6 CSVs would touch dozens of imports and path
  literals (the style lock reads `deck_builder.py` and five other root files by path) for no gain in clarity
  that `INDEX.md` does not give; the brief said prefer fewer, safe moves. Only clearly retired items leave the root.
- **Audio merged into one folder** because no key had a file in both `audio/` and `audio_a2/`, and because
  `build_apkg` never read the other folder for a given card kind (checked by `tidy_moves.py plan`: an audio clash
  stops the plan). `audio_source.tsv`'s `file` column is rewritten to the new paths (674 rows, nothing else).

## 3. Steps

1. **Inventory** on the Mac (`tidy_moves.py plan`): every file in the seven picture folders, `audio/`,
   `audio_a2/` and the root candidates; the current picture of every card computed with `build_apkg`'s own
   `find_image` / `find_a2_image` in its own order, *before* anything moves; tracked/untracked from `git ls-files`;
   sha1 and size per file. Output `moves_2026-10-24.csv` (3,239 rows).
2. **Baseline packages** before the move: rc4 (A1, sha256 42e8456a…) and a fresh A2 build to a scratch path.
3. **Code and docs** in the cloud clone: `build_apkg.py` (`IMAGE_DIR`, `AUDIO_DIR`), `build_recorder.py`,
   `tools/ingest_takes.py` (`_history`), `tools/rename_keys.py` (media dirs, live/history lists),
   `tools/golden_set.py`, the four `gen.py` drivers and `a2_adapter.py` (root three levels up; `OUT`/`HIST`/`META`),
   `gen_phrases.py`, `qa_images.py` defaults, `audio_source.tsv`, `.gitignore`, `a2_build/RECORDING_GUIDE.md`,
   README, spec §4/§7/§9/§10/§12 + new §13 (patch release 3.4.1 via `spec_release.py`), `tools/check_layout.py`
   (+ pre-commit hook, + a warning pass in `build_apkg.py`), `INDEX.md`.
4. **Tracked moves** (`tidy_moves.py apply --tracked`, `git mv`, 1,243 files) in the clone; commit; push.
5. **Untracked moves** on the Mac in the Proton folder (`apply --untracked`, 1,996 files, `os.rename` +
   sha1 before/after, idempotent); then `git fetch` + `reset --hard` to bring the tracked moves in; move any Proton
   conflict copies to `.git/_sync_conflicts/`; `tidy_moves.py verify`.
6. **Verify**: rebuild A1 and A2 to a scratch path; `verify_apkg.py --against` rc4 and the A2 baseline with the
   key maps: 0 field differences, same media set and hashes, same GUIDs. `style_lock.py check`,
   `rename_keys.py --verify` 0 FAIL, `check_layout.py` clean, grep for stale paths in live code and docs.
7. **Recorder**: `build_recorder.py A2` on the Mac (dests are now `media/audio/…`); diff the page: only the data
   line and the dests change, IndexedDB `lt_recorder_A2_afb2ebe2` and the KEY_MAP migration untouched.
8. Commit from outside Proton, push, sync Proton, re-check after 30–60 s. Write `APPLIED_tidy_2026-10-24.md`.

## 4. Not moved, and why

- Live code and live data at the root (above). `_apkg_media/`, `_qa/`, `__pycache__/`: caches, regenerate freely.
- `style_lab/` (owner: keep as a record), `a2_rebase/`, `sources/`, `_archive/`, `_TO_DELETE/`: already in place.
- `recorder_A2.html`: stays at the root under the same name (the owner records today; its takes are in Chrome).
- `fonts/_superseded/`: the retired font pair, not card media.
- `wordlist_a2_pending.csv`: still read by `build_recorder.py`, `qa_images.py`, `gen_phrases.py`.
- Pictures named by a merged or deferred id (`out_phrases_v3/A2-1149.png`, `out_deck_a2/A2-0219.png`, …) and
  `yes_no.png`: not cards; into `_history/` with their batch.
- `edit_inset.py` (`a2_build/additions_round2/`) and `restore_before.py` (`a2_build/hand_fixes/`) still carry the
  old folder names; they are round tools (history) and are only used when the owner asks for a masked edit —
  fix their paths then.
