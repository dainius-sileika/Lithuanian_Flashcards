# Merges decided by the owner, 2026-10-19 — exact data changes (plan for the executor)

Four merges, three overlaps left alone. Plan only: nothing below has been applied. The pattern follows
`a2_build/src/apply_benchmark.py` §3 (deferrals): a row that leaves `a2_wordlist.csv` keeps its id and every column in a
side file, `id_map.csv` keeps the id reserved, and the step is idempotent so a rebuild by `build_a2.py` + the apply
scripts restores the same state.

## Identity rule, stated once

- A note's GUID is `genanki.guid_for(<key>)` (`build_apkg.py` IDENTITY block). The **surviving key keeps its GUID**, so
  every learner who already has that card keeps its scheduling; only its fields change at re-import.
- The **absorbed key is dropped from the build**: its row leaves `a2_wordlist.csv`, so `add_a2_notes()` never sees it and
  no note is written. Anki's importer does not delete notes, so a learner who already has the absorbed card keeps it as
  an orphan until they follow the project's standing advice (delete the deck, import the new package). No key is ever
  reused or renamed; the dropped id stays in `id_map.csv` with a `merged_into` mark so `build_a2.py` cannot hand it out
  again.
- `english_alt` exists in `a2_wordlist.csv` (apply_benchmark §2, `" | "`-joined) but `build_apkg.py` does not put it on
  the card. It is the right home for the absorbed gloss as data; what the learner *sees* of the absorbed word is the
  back-of-card usage line (`context_notes.csv`), as the owner specified for Sudie. If he wants the alt gloss visible on
  the other three, the one-line change is to append `english_alt` to the gloss div in the GO template — a schema-free
  change (same fields), so no note-type conflict.

## Mechanics common to all four

1. New side file **`a2_build/merged_keys.csv`**: the full `a2_wordlist.csv` columns + `merged_into`, `merged_on`,
   `merge_note`. The four absorbed rows move there verbatim (as deferrals move to `deferred_B1.csv`).
2. **`a2_build/id_map.csv`**: keep the four ids; add a column `merged_into` (empty for every other row) so the id stays
   reserved and self-explaining. No renumbering.
3. **`a2_build/restage_bubbles.csv`**: the absorbed key's row gets `render = "no (merged into <key>)"` and
   `merge_with = <key>` — exactly the 0899/0901/0902/0904 pattern already in the file. Its staging text is replaced by
   `MERGED into <key>` so `build_situations.py` writes no prompt for it.
4. **`study_order.csv`**: rebuild with `python3 build_study_order_v2.py` after step 1 — it reads `a2_wordlist.csv`, so the
   absorbed keys vanish and the survivors keep their slots (positions after each removed row shift up by one; `due` is
   applied only to new cards, so this costs nothing). Do not hand-edit the order file.
5. **`a2_build/recording_list.csv`**: drop the absorbed keys' takes (A2-1149 take 1004, A2-1187 take 1042; 1944/1958 are
   not on the list). No audio is lost — none has been recorded for them (`audio_a2/` has no file for any of the four).
6. **`a2_build/context_notes.csv`**: see each merge. `load_usage()` keys by card key, so a note on a dropped key would be
   silently unused — remove or re-key it.
7. Idempotence: add the four moves to an `apply_merges.py` (or a §4 in `apply_benchmark.py`) keyed on `merged_keys.csv`,
   run after `apply_benchmark.py`; `build_warnings.txt` stays empty.
